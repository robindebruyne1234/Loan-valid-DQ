## L-19 · Scope against the brief {#l19}

**Area** process · **Severity** Medium (perception) · <span class="tag open">TALK TRACK</span>

The brief expects 1–2 days and warns: *"If you spend most of your time on infrastructure or tooling
setup, you have misread the brief."* The repository contains a two-factor login enforced in the
database, a web walkthrough, a deployment guide for a public host, a 55-slide deck, simulated
layer-owning agents and a native-Windows/Ollama path. An interviewer will ask.

**How to answer.** (1) Tasks 1–3 were built and evaluated first, and the stack stayed deliberately
minimal — one database, SQL files, plain Python, a Makefile. (2) The extras were added on explicit
request and each makes a *governance* point rather than an infrastructure one: identity enforced in
the engine, onboarding as data, a model that runs fully offline. (3) What you would cut, in order:
the deployment guide, the simulated agents, the web page (keep the console demo). Do not deny the
time spent and do not apologise for it.

## L-20 · Two working copies {#l20}

## P-01 · The month-end closing posting by balance chain (D028) {#p01}

the postings, the lowest id among the chain ends is the documented fallback and the row is marked
`closing_basis = 'ambiguous'`. The reconciliation rules read the closing balance the same way.

## P-02 · Intent verification in the runner and the web app (D029) {#p02}

The model returns an IR next to its SQL; `src/sql_ir.py` checks the IR against the certified
metrics, resolves every column scope by scope, evaluates the period filter day by day over the
book's calendar, refuses undeclared or fan-out joins, unrequested filters and pivots, and only then
logs in, plans (EXPLAIN), executes under RLS and recomputes the metric from the IR. One entry point
(`run_questions.verify_and_execute`) serves both paths; a refusal is fed back for the one retry.
`tests/test_sql_ir.py` (66 tests) covers the observed gender failure, quarter inclusion and
exclusion, the wrong date column, fan-out, missing periods and grouping, malformed IRs, and both
application paths with a scripted model.

## P-03 · The verifier's first run refused two correct answers {#p03}

On its first live run the verifier refused Q9 (the model wrote the composite grain as the string
`"account_id, month_end_date"` instead of a list) and Q6 on the first attempt (months reported as
numbers, which the recomputation did not accept). Both answers were right; both were verifier bugs.
They were fixed and pinned by tests, that run was archived with an explanation, and both suites were
re-run on the fixed code: **10/10** and **4/4**, all on the first attempt.

**Lesson.** A checker needs tests against *correct* answers as much as against wrong ones; otherwise
it trades false answers for false refusals.
