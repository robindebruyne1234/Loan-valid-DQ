# The Governed Data Product for AI -- Berka (PKDD'99)

Raw banking tables turned into a trusted, documented, entitlement-aware data
product that an AI assistant can query correctly. Take-home submission.

```
make up && make all          # Linux / WSL / Docker: the whole pipeline and every deliverable
scripts\windows.ps1 build    # native Windows with a local PostgreSQL (see docs/LOCAL_LLM_WINDOWS.md)
make test                    # or: scripts\windows.ps1 test
```

## Results in brief

Figures from the build of the delivery commit; `docs/DELIVERY_AUDIT.md` maps
each to its source.

- **Task 1, data quality.** 124 rules executed (89 hand written in
  `dq/dq_rules.yaml`, 35 from a per-column completeness sweep) across
  completeness, uniqueness, referential integrity, validity, cross-table
  consistency and reconciliation. Every rule carries a severity and the reason
  for it; the loader refuses one without. 19 fire as 14 defect types: 1 row
  quarantined (`block`), 440 flagged (`warn`), the rest logged (`info`). The
  rules are proven by 20 seeded defects (`tests/test_dq.py`).
- **Task 2, model and semantic layer.** A star schema (4 dimensions, 1 bridge,
  2 base facts, 1 derived month-end fact, 3 curated views), verified after
  every build, with `core = stg - quarantine` on rows and money. The semantic
  layer is validated against the live database: a column that does not exist,
  a false grain, a wrong join cardinality or a metric on a missing column
  fails the build. A problematic loan is status B or D: 76 of 682 = 11.14%
  (assumption A4, awaiting business confirmation).
- **The ten questions.** Claude Sonnet 5.5 answered all ten on the first
  attempt and **10 of 10 match** the hand-written reference (run of
  2026-10-25; that run used the semantic pack from before the audit). A local
  Ollama model (qwen2.5-coder:3b) is an optional free provider; its separate
  run scored 6 match, 2 partial, 2 mismatch.
- **Task 3, entitlements.** Row level security on the core tables,
  `security_invoker` views on top, identity from `session_user` after a
  two-factor login. Measured by logging in as each role:

  | role | clients | accounts | loans | transactions |
  |---|---:|---:|---:|---:|
  | `cro_global` (portfolio of every client) | 5,369 | 4,500 | 682 | 1,056,319 |
  | `rm_north` | 1,481 | 1,241 | 179 | 294,622 |
  | `rm_south` (1,386 in its book + 1 delegated client) | 1,387 | 1,158 | 195 | 272,770 |
  | `rm_unassigned` (no portfolio) | 0 | 0 | 0 | 0 |
  | `client_3764` (a disponent: one account, not its owner) | 1 | 1 | 1 | 439 |

  Nine bypass attempts and the cross-client attempts in `tests/test_rls.py`
  are refused. Onboarding is inserts and one credential; offboarding is one
  `UPDATE`.

**Known limitations** (detail in `docs/DELIVERY_AUDIT.md`): the SQL guard
proves a query is safe, not that it answers the question, and the intent
checker is a prototype only; the month-end balance breaks same-day ties by the
highest `trans_id`, which is not chronological (A14, caveat C2); the recorded
Claude run predates the current semantic pack.

```
              00 schemas | 10 staging | 30 core | 40 ai views | 50-51 security
              60 reference queries | 70 defect injector

```

## How to re-run one step

```
make ingest        # load the raw files, verify counts, hash each file
make profile       # build stg, profile every column, list candidate defects
make dq            # run all rules, quarantine, flag, write the defect report
make model         # build core, verify it, restore the ai views
make reference     # run the hand-written reference queries (ground truth)
make semantic      # validate the semantic layer and render the context pack
make entitlements  # apply the policies and seed the demo portfolios
make questions     # ask the LLM the 10 questions (the recorded run)
make evaluate      # compare the LLM answers to the reference answers
make deliverables  # workbook + DDR + ZIP
```

On Windows each is `scripts\windows.ps1 <step>`; `questions-local` and
`evaluate-local` write a local model's run to `dq/results/local/` instead.

## Environment notes

- **PostgreSQL.** Built on 16 (Linux, docker compose or a native cluster) and
  on 18 (native Windows). Identical DDL, policies and tests.
- **The data.** The eight original `.asc` files are in `data/raw/`, from the
  public mirror `github.com/jlacko/berka-dataset`, verified against the
  published row counts (4,500 / 5,369 / 5,369 / 892 / 682 / 6,471 / 1,056,320 /
  77, 1,079,680 in all). `data/raw/provided/` is empty: no bank-supplied copy
  was received; the loader prefers that directory if one is dropped there.
- **The LLM.** The local Claude CLI called as a sandboxed completion (no tools,
  no MCP, no filesystem, no database), or Ollama locally. Full disclosure in
  `AI_DISCLOSURE.md`.
- **Python dependencies.** `psycopg[binary]`, `PyYAML`, `sqlglot`, `openpyxl`,
  `python-docx`, `pytest`. LibreOffice (Linux) or Microsoft Word (Windows)
  converts the DDR to PDF and verifies its page count.
